GitHub Copilot のエージェント モードは自律的に動作し、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分を確認し、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じる利用者向けにライト モードも追加してほしいという依頼がありました。新しい会話を最初から始めず、既存のセッションに追加の作業を指示します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取り、編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再試行させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ツールの使用 (ターミナル コマンドの実行など) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するコマンドだけを承認してください。

5. ハイ コントラスト モードの実装が完了するまで待ちます。最後に、変更内容の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたので、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けることで、エージェントは既存の作業、変更したコンポーネント、スタイルの方針、local storage の使い方を引き継げます。

1. Copilot Chat の入力欄に次の追加プロンプトを送ります。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは、すでに行った変更を確認してからライト モードの追加を提案します。
3. 新しい編集を1つずつレビューし、**Keep** または **Undo** を使います。
4. エージェントの方向性が希望と異なる場合 (たとえば、気に入らない方法でトグル UI をリファクタリングしようとする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すより短時間で調整できます。追加のプロンプトを使って、変更を依頼できます (「CSS を簡略化し、セレクターの重複ではなく CSS 変数を使う」など)。方向を調整したり (「トグルを3つに増やさず、既存の設定パネルにライト モードを追加する」など)、範囲を広げたり (「両方のトグルにキーボード ショートカットも追加する」など) できます。

## 変更されたファイルをレビューする

変更をコミットする前に、エージェントが編集したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルをすべて確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントから与えられたアクセシビリティの方針 (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視して調整しました。各ファイルの編集をレビューし、変更を承認または取り消し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 作業中のセッションに追加のプロンプトを送り、方向を調整しました。

次の[レッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
